# Mukhtabar (مختبر)

A local study tool for exam preparation. You give it your own study material as PDFs and it:

- extracts and chunks the text (built for Arabic, including right-to-left layouts and mixed Arabic/English);
- builds a map of study topics with an AI model;
- generates multiple-choice questions grounded in your material, each with the passage it comes from;
- quizzes you in the terminal, tracks your mastery per topic, and focuses practice on the topics that cost you the most exam points;
- schedules reviews with spaced repetition and runs full mock exams.

Everything is stored in a local SQLite file. A model is only called to build the topic map and to generate questions. Quizzes, practice and reports make no model calls.

> **Disclaimer**
>
> - Mukhtabar is an **unofficial study aid**. It is **not affiliated with, endorsed by, or connected to any exam body**, regulator, or training provider.
> - Questions and topics are **generated by AI and can be wrong**: wrong answers, misleading options, or outdated facts. Each question shows the passage it was based on. **Always verify against your official study materials.**
> - **No study material is included.** You bring your own PDFs, and you are responsible for having the right to use them. Your material is sent to the model provider you choose when you build topics and generate questions.

## Setup

You need Python 3.11 or newer.

```bash
git clone https://github.com/joodk1/mukhtabar.git
cd mukhtabar
python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS / Linux:  source .venv/bin/activate
pip install -e .            # add [dev] for the tests: pip install -e ".[dev]"
```

Model calls go through [LiteLLM](https://docs.litellm.ai/), so any provider it supports works. Create a `.env` file in the project folder with your key and the model to use. `.env` is ignored by git, so it never ends up in the repo. For example, with Google Gemini:

```
GEMINI_API_KEY=your-key-here
MUKHTABAR_MODEL=gemini/<model-name>
```

For another provider, use its usual variable (for example `OPENAI_API_KEY`) and a LiteLLM model name. You can also pass `--model` to any command that calls a model.

## Usage

All commands take `--db PATH` to choose the database file (default `mukhtabar.db` in the current folder). A *study set* is one exam's material. You name it with `--set`.

### 1. Ingest your PDFs

```bash
python -m mukhtabar.ingest add --set "My Exam" book.pdf summary.pdf
```

The language is detected automatically (override it with `--language ar`). Repeated headers and footers are removed. Scanned PDFs without a text layer are not supported.

### 2. Build the topic map

```bash
python -m mukhtabar.topics estimate --set "My Exam"     # calls, tokens and estimated cost; no model call
python -m mukhtabar.topics build    --set "My Exam"     # shows the estimate and asks before calling the model
python -m mukhtabar.topics list     --set "My Exam"
```

You can tidy the map with `rename`, `merge` and `delete`. If you know how much each chapter counts in the exam, set it (in percent). Practice, reports and mock exams then follow those weights:

```bash
python -m mukhtabar.topics weights --set "My Exam"
python -m mukhtabar.topics weight  --set "My Exam" --chapter 1 --percent 12
```

### 3. Generate questions

```bash
python -m mukhtabar.questions estimate --set "My Exam" --all
python -m mukhtabar.questions generate --set "My Exam" --all          # 6 questions per topic
python -m mukhtabar.questions generate --set "My Exam" --all --calc   # optional: calculation questions where the material has worked examples
```

Questions are cached in the database, so later quizzes cost nothing. Every question is checked for a word-for-word evidence quote from your material. Questions that copy practice questions in your material are rejected.

### 4. Study

```bash
python -m mukhtabar.quiz diagnostic --set "My Exam"                    # 30 questions spread by chapter weight
python -m mukhtabar.quiz diagnostic --set "My Exam" --mode adaptive    # aims at weak, high-value topics
python -m mukhtabar.quiz practice   --set "My Exam"                    # 20 questions on your weakest topics
python -m mukhtabar.quiz mock       --set "My Exam" --minutes 60       # 50-question mock exam (timer optional)
python -m mukhtabar.quiz report     --set "My Exam"                    # topics ranked by exam points to gain
python -m mukhtabar.quiz due        --set "My Exam"                    # topics due for review
```

Answer with أ/ب/ج/د, a–d or 1–4, or `q` to stop (your answers so far are kept). If your terminal shows Arabic letters unjoined or reversed, add `--visual`.

- **Mastery:** each topic's mastery is a recency-weighted average of your answers. It's marked provisional until the topic has 4 answers.
- **Practice:** practice picks the topic with the most exam points still to gain. Within it, it asks questions you haven't seen first, then the ones you got wrong.
- **Spaced repetition:** once a topic has 3 answers, it goes into a review box (1, 2, 4 or 7 days) based on its mastery.

### Back up your progress

```bash
python -m mukhtabar.backup --db mukhtabar.db      # writes backups/mukhtabar-YYYY-MM-DD.db next to the database
```

## Privacy

- Your PDFs, the database and backups stay on your computer. `.gitignore` excludes `*.db`, `.env` and `samples_private/`.
- Text is sent only to the model provider you configure, and only when you build topics or generate questions. Those commands show an estimate and ask before calling the model.

## Tests

```bash
pip install -e ".[dev]"
pytest
```

The tests use small synthetic Arabic PDFs in `tests/fixtures/` and make no model calls.
